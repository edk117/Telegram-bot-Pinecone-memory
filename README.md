# Telegram-бот с памятью в Pinecone

Проект демонстрирует работу персонального Telegram-помощника с векторным поиском. Бот ищет справочные факты о брендах и личные воспоминания пользователя в Pinecone, затем передаёт найденный контекст языковой модели через ProxyAPI.

**Важно:** текущая реализация не гарантирует, что ответы содержат только факты из Pinecone. Модель может использовать собственные знания или ошибаться; ссылки на источники и проверка каждого утверждения не реализованы.

## Состав проекта

| Файл | Назначение |
| --- | --- |
| `bot.py` | Обработка сообщений Telegram, поиск контекста, генерация ответа и сохранение личных фактов. |
| `pine.py` | Клиент Pinecone: запись, чтение, поиск и удаление векторов. |
| `test.py` | Пример фактов о Gucci и CHANEL и скрипт для поиска по индексу. Это не автоматический набор тестов. |
| `requirements.txt` | Зависимости Python. |
| `.env` | Локальные ключи и настройки. Файл не должен попадать в Git. |

## Как работает бот

1. Пользователь отправляет текстовое сообщение боту в личном чате Telegram.
2. Бот получает векторное представление сообщения (эмбеддинг) через ProxyAPI, используя модель `openai/text-embedding-3-small`.
3. Pinecone ищет до 10 ближайших записей в личном namespace пользователя и до 10 в общем namespace. Это максимальное количество результатов для каждого поиска, а не гарантия их релевантности.
4. Бот передаёт модели сообщение, до двух последних обменов сообщениями и найденные тексты. Для поиска по общей базе также учитываются предыдущие вопросы пользователя.
5. Модель формирует ответ и может предложить до трёх новых личных фактов. Бот сохраняет подходящие факты в личном namespace.
6. Ответ отправляется в Telegram; длинный текст разбивается на части.

В модель передаются только найденные записи, у которых в метаданных есть текстовое поле `text`. История диалога хранится отдельно для каждого пользователя в оперативной памяти и теряется при перезапуске процесса. Она нужна для коротких уточнений, например «А где был первый магазин?» после вопроса о Gucci.

## Данные в Pinecone

Проект использует один заранее созданный индекс и два вида пространств имён (namespaces):

| Namespace | Содержимое | Использование |
| --- | --- | --- |
| По умолчанию: `""` в коде, `__default__` в интерфейсе Pinecone | Общие справочные факты, например о брендах, если они были туда загружены. | Поиск по общей базе. |
| `telegram-user-<Telegram ID>` | Личные факты конкретного пользователя, сохранённые ботом. | Поиск и запись личной памяти. |

Пользовательский ID подставляется автоматически. Записи в разных namespace изолированы: поиск в одном не возвращает записи из другого. Автоматическая запись новых фактов выполняется только в личный namespace.

Индекс должен принимать векторы той же размерности, что и эмбеддинги используемой модели. Для осмысленного поиска загружайте записи и создавайте поисковые векторы одной и той же моделью эмбеддингов. В метаданных каждой записи укажите строковое поле `text` с исходным фактом.

`test.py` содержит примеры фактов, но **не загружает их при обычном запуске**: цикл записи в Pinecone закомментирован. Запуск скрипта выполняет только пример поиска. Если раскомментировать цикл загрузки, он создаст эмбеддинги и запишет факты в namespace по умолчанию. Записи с теми же ID в этом namespace будут перезаписаны. Перед загрузкой проверьте индекс, ID и существующие данные; операции с внешними сервисами могут быть платными.

## Требования

- Python 3.12 и `pip` (локальное окружение использует Python 3.12).
- Доступ к Telegram и токен бота.
- Ключ ProxyAPI с доступом к модели эмбеддингов и выбранной модели ответов.
- Ключ Pinecone и заранее созданный совместимый индекс.
- Сетевой доступ к Telegram, ProxyAPI и Pinecone.

Проект использует пакеты `pyTelegramBotAPI`, `openai`, `python-dotenv` и `pinecone`. Их версии в `requirements.txt` не закреплены.

## Установка и настройка

Выполняйте команды из каталога проекта.

1. Создайте виртуальное окружение и установите зависимости:

   ```bash
   python3.12 -m venv .venv
   .venv/bin/python -m pip install -r requirements.txt
   ```

2. Создайте рядом с `bot.py` файл `.env` и задайте свои значения:

   ```dotenv
   TELEGRAM_BOT_TOKEN=токен_бота
   OPENAI_KEY=ключ_ProxyAPI
   PINECONE_API_KEY=ключ_Pinecone
   PINECONE_INDEX_NAME=имя_индекса
   # Необязательно: если не задано, используется openai/gpt-5-mini.
   OPENAI_CHAT_MODEL=openai/gpt-5-mini
   ```

   Токен Telegram-бота можно получить через BotFather. Значения выше являются примерами, а не рабочими ключами. Не публикуйте `.env` и не отправляйте ключи боту.

3. Убедитесь, что индекс Pinecone существует и соответствует модели эмбеддингов. Если нужны ответы о брендах, заранее загрузите соответствующие записи в namespace по умолчанию.

## Запуск

```bash
.venv/bin/python bot.py
```

Откройте бота в Telegram, отправьте `/start` и задайте вопрос в личном чате. Бот также поддерживает `/help`. Команды и обычные текстовые сообщения обрабатываются только в личных чатах; остальные виды сообщений текущей реализацией не обрабатываются. Процесс должен оставаться запущенным для получения сообщений. Для остановки нажмите `Ctrl+C` в терминале.

Проверить пример векторного поиска можно отдельно:

```bash
.venv/bin/python test.py
```

Скрипт отправляет запрос на создание эмбеддинга через ProxyAPI и ищет в namespace по умолчанию. Он выводит ID, оценку сходства и текст найденных записей; требует настроенных ключей и сетевого доступа.

## Чтение записей по ID

В Pinecone откройте нужный индекс и namespace, затем посмотрите поле `text` в metadata записи. Для программного чтения используйте `PineconeVectorClient.fetch_vectors`:

```python
import os

from dotenv import load_dotenv
from pine import PineconeVectorClient

load_dotenv()
client = PineconeVectorClient(index_name=os.environ["PINECONE_INDEX_NAME"])

# Для общей базы используйте namespace="".
result = client.fetch_vectors(["6"], namespace="")
print(result)
```

Для личной памяти укажите `namespace="telegram-user-<Telegram ID>"` и реальные ID записей. Список доступных ID и содержимое индекса зависят от фактически загруженных данных.

## Безопасность и ограничения

- Тексты сообщений и найденный контекст передаются через ProxyAPI. Личные факты могут сохраняться в Pinecone. Не отправляйте пароли, ключи и другие чувствительные сведения.
- Инструкция модели запрещает сохранять чувствительные сведения, но автоматическое извлечение фактов не гарантирует их обнаружение и исключение.
- Модель может неправильно выбрать, интерпретировать или дополнить найденные факты. В коде нет порога сходства, ссылок на источники или гарантии ответа только по Pinecone.
- Личные namespace отделяют данные пользователей при обычной работе бота, но сами по себе не заменяют настройку доступа к аккаунту и ключам Pinecone.
- Если поиск или генерация ответа завершатся ошибкой, бот отправит общее сообщение об ошибке. Если не удалось сохранить новый факт, бот сообщит об этом отдельно.
- История хранится только в памяти процесса. При перезапуске она пропадает; личные факты, успешно записанные в Pinecone, остаются в индексе.

## Проверка зависимостей

```bash
.venv/bin/python -m pip check
```

Эта команда проверяет совместимость установленных пакетов, но не проверяет доступность внешних сервисов и корректность ответов бота.
